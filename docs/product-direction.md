# 陪伴猫 产品方向

> 状态：草稿，待确认
> 最后更新：2026-11-16（加入引擎设计、CEL 表达式、多入口功能、依赖库选型）
> 说明：本文记录产品定位、核心概念和已经做出的决定，是之后各期规格文档的依据。每期要做的具体内容，在 `docs/specs/` 下单独写规格。
> 标记含义：【已定】用户已确认；【建议】我提出、尚未单独确认；【待定】还没有结论。

## 1. 一句话定位

**陪伴猫：用订阅的规则，把各种服务的能力带到任何网页上。** 【已定】

它是一个运行在脚本猫（ScriptCat）里的用户脚本。网页角落趴着一只睡觉的卡通猫，平时不打扰你；你需要的时候，它用规则里定义好的引擎帮你翻译、做题、跳过广告、自动操作网页。

## 2. 谁在用

| 角色 | 想做什么 | 怎么用 |
|---|---|---|
| 普通用户 | 装上就能用，偶尔填个 API Key | 小猫气泡 + 设置窗口；订阅官方规则 |
| 规则作者 | 让陪伴猫支持新的服务、新的网站、新的能力 | 只写 JSON 规则包，不写代码 |
| 其他脚本的开发者 | 在自己的脚本里调用陪伴猫的引擎 | 【待定】是否开放，见第 17 节 |

## 3. 产品原则

1. **引擎是核心，场景要薄。** 竞争力在能力引擎这一层。划词、做题、自动化等场景只是调用方，新增场景最好只需要写规则。【已定】
2. **陪伴猫本身是一个外壳，功能都来自规则。** 划词翻译这样的功能，以及它带来的设置项、左侧菜单、气泡开关，都由规则包声明；代码只提供外壳和一组基础组件。没有规则时，陪伴猫什么都不会。【已定】
3. **规则只是 JSON 加受限表达式，不执行代码。** 订阅规则包不等于运行别人的代码。表达式用 CEL：只能计算、没有副作用、没有无限循环，只能调用白名单里的纯函数。【已定】
4. **能力的种类是开放的。** 能力用"契约"定义，规则包可以声明新契约；加天气、笑话这类能力不需要改代码。【已定】
5. **Key 不离开本机，换地址先问你。** 规则里不能写 Key；规则更新后请求域名变了，必须你确认才会继续发 Key。【已定】
6. **有把握才自动做，没把握先问你。** 所有能力的结果都带统一的置信度。低于规则设定的门槛时，小猫只提示、不动手。【建议】
7. **不替你做不可撤销的事。** 做题不自动交卷，自动化不自动付款或提交表单。【建议】
8. **小猫不打扰。** 平时安静地睡在角落；每个网站都能单独关掉划词或隐藏小猫。【已定】

## 4. 整体结构

```
规则包（JSON）── 声明 ──┬─ 功能 features：设置项 · 触发 · 执行 · 展示 → 变成菜单页、气泡开关、页面上的猫爪和卡片
                        ├─ 引擎 providers：实现哪些契约、怎么调用
                        └─ 契约 contracts：新的能力类型

代码（陪伴猫外壳）── 提供 ──┬─ 外壳：小猫、气泡、设置窗口，以及自带的「引擎 / 规则 / 通用」三页
                            ├─ 能力引擎：契约 → 实现 → 调用管道 → 路由策略 → 统一结果
                            └─ 基础组件：触发器 · 展示位置 · 视图组件 · 动作 · 设置类型
```

功能只用规则把基础组件拼起来；引擎层负责把"调用契约"变成对外部服务的请求。

### 代码和规则的分工

| 由代码提供（陪伴猫外壳） | 由规则声明 |
|---|---|
| 小猫、气泡和设置窗口的外框 | 有哪些功能，叫什么名字，用什么图标 |
| 设置窗口自带的「引擎」「规则」「通用」三页 | 功能的设置项，会自动生成成设置页 |
| 触发器：选中文字、快捷键、页面加载完、元素出现、网址变化、脚本猫菜单 | 功能在哪些网站生效（`match`），由哪个触发器启动 |
| 展示位置：选区旁边、小猫气泡、页面提示、页面内嵌 | 功能执行哪些步骤（调用哪个契约、用什么策略） |
| 视图组件，包括专门显示多引擎结果的 `result-list` | 结果用哪些组件、怎么排列 |
| 动作：复制、固定、重试、去配置引擎，以后加上点击和填写 | 哪些设置项要放进小猫气泡（`quick`） |
| 设置类型：开关、单选、语言、引擎多选、文本、数字、快捷键 | 引擎和契约 |

## 5. 核心概念

| 概念 | 含义 |
|---|---|
| 规则包 | 一个订阅地址对应一个 JSON 包，里面有功能、契约、引擎、网站规则；带全局唯一的 `id` 和版本 |
| 功能 | 规则包声明的一个完整功能（比如翻译）：共用设置 + 若干入口。它会在设置窗口左侧加一个菜单页，可能往小猫气泡里加开关和按钮 |
| 入口 | 功能里的一种用法（比如划词翻译、网页对照翻译）：自己的设置 + 触发 + 执行 + 展示 |
| 视图模板 | 规则里用基础组件拼出来的一块界面（比如结果卡片），入口用 `use` 引用 |
| 契约 | 一种能力的类型签名：输入格式、输出格式、说明、样例、默认视图，例如 `translate`、`choose`、`weather/current@1` |
| 引擎 | 一个外部服务，声明自己实现了哪些契约、怎么实现，例如 DeepSeek、Google 翻译、Jev |
| 调用 | 场景或规则以"契约 + 输入 + 策略"发起，例如 `call("translate", {...}, { strategy: "all" })` |
| 结果 | 统一的结构：输出 + 置信度 + 引擎 + 耗时 + 是否缓存 + 费用 |
| 网站规则 | 按网址匹配，描述在这个网站上做什么（做题、自动化等），通过调用契约完成 |
| 视图 | 用来展示契约结果的声明式组件树 |

## 6. 规则包格式

```jsonc
{
  "$schema": "https://…/companioncat/schema/v1.json",   // 编辑器据此补全和报错
  "schema": 1,
  "id": "official-translate",
  "name": "翻译",
  "version": "2026.11.16",
  "contracts": [ … ],   // 可选：新的能力类型，见第 8 节
  "providers": [ … ],   // 引擎，见第 9 节
  "views":     { … },   // 视图模板，见第 7 节
  "features":  [ … ],   // 功能，见第 7 节
  "sites":     [ … ],   // 按网站微调功能的参数，比如 GitHub 上哪些元素算段落
  "overrides": { … }    // 只在本地规则里使用：修改订阅里的引擎或功能
}
```

- **组合方式**【已定】：
  - 多个规则包同时订阅，靠上的优先；
  - `extends` 基于已有的引擎新建，只写不同的字段；可以继承别的包里的引擎，写成 `包id/引擎id`；
  - 本地规则的 `overrides` 修改订阅里的内容，订阅更新后修改仍然保留；
  - 对象逐层合并，数组整个替换，`null` 表示删除这个字段；继承最多 5 层。
- **出错处理**【已定】：继承的对象找不到、出现循环、缺少必填字段、表达式写错时，只停用出错的那一个引擎或入口，界面上写明原因，其他照常工作。
- **更新**【已定】：打开网页时，距离上次检查超过一天就自动检查；拉取失败时继续用缓存，并在界面上提示。
- **默认订阅**【已定】：首次安装就订阅官方的「翻译」和「常见大模型」两个规则包。
- **规则 JSON Schema**【已定】：发布一份机器可读的 Schema，供编辑器补全、本地规则校验和第二期 AI 写规则使用。

## 7. 功能：「翻译」是怎么用规则定义的

一个功能可以有**多个入口**，入口之间可以共用设置。「翻译」功能有两个入口：划词翻译、网页对照翻译。【已定】

```jsonc
"features": [{
  "id": "translate",
  "name": "翻译",
  "icon": "languages",
  "match": ["*://*/*"],

  // 两个入口共用的设置
  "settings": {
    "to":         { "type": "language", "title": "翻译成", "default": "zh-CN", "quick": true },
    "swapIfSame": { "type": "boolean", "title": "中英互译", "default": true }
  },

  "entries": [
    {
      "id": "selection", "name": "划词翻译",
      "settings": {
        "siteEnabled": { "type": "boolean", "title": "在这个网站划词翻译", "scope": "site", "default": true, "quick": true },
        "confirm":     { "type": "enum", "title": "选中文字后", "default": "paw",
                         "options": { "paw": "先伸出猫爪", "none": "直接翻译", "alt": "按住 Alt 才翻译" } },
        "engines":     { "type": "engines", "capability": "translate", "title": "卡片里显示哪些引擎", "max": 4, "quick": "first" }
      },
      "triggers": [{ "on": "selection", "enabled": "{{ settings.siteEnabled }}", "confirm": "{{ settings.confirm }}",
                     "ignoreIn": ["input", "textarea", "[contenteditable]"] }],
      "run": [
        { "set": { "to": "{{ settings.swapIfSame && selection.lang == settings.to ? 'en' : settings.to }}" } },
        { "call": "translate", "strategy": "all", "engines": "{{ settings.engines }}", "stream": true,
          "input": { "texts": ["{{ selection.text }}"], "to": "{{ vars.to }}", "context": "{{ selection.sentence }}" },
          "as": "results" }
      ],
      "present": {
        "surface": { "type": "near-selection", "pinnable": true, "closeOn": ["escape", "outside-click", "new-selection"] },
        "view": { "use": "translation-card", "with": { "results": "{{ results }}", "to": "{{ vars.to }}" } }
      }
    },
    {
      "id": "page", "name": "网页对照翻译",
      "settings": {
        "auto":   { "type": "boolean", "title": "打开这个网站时自动对照", "scope": "site", "default": false },
        "show":   { "type": "enum", "title": "显示方式", "default": "both", "quick": true,
                    "options": { "both": "原文下面显示译文", "only": "只看译文" } },
        "engine": { "type": "engine", "capability": "translate", "title": "用哪个引擎" }
      },
      "triggers": [
        { "on": "command", "title": "对照翻译这个网页", "hotkey": "Alt+A", "quick": true },
        { "on": "page-load", "enabled": "{{ settings.auto }}" }
      ],
      "toggle": true,
      "select": { "blocks": "{{ has(site.blocks) ? site.blocks : 'auto' }}",
                  "exclude": ["pre", "code", "nav", "[translate=no]"], "lazy": "viewport", "watch": "mutations" },
      "run": [
        { "call": "translate", "strategy": "first", "engines": ["{{ settings.engine }}"], "batch": "blocks",
          "input": { "texts": "{{ blocks.map(b, b.text) }}", "to": "{{ settings.to }}" }, "as": "results" }
      ],
      "present": {
        "surface": { "type": "inline-after", "target": "block", "hideSource": "{{ settings.show == 'only' }}" },
        "view": { "type": "text", "style": "inline-translation", "value": "{{ result.output.texts[0] }}" }
      }
    }
  ]
}]
```

**视图模板**：结果卡片也是规则（`views.translation-card`），由基础组件拼成，入口用 `use` / `with` 引用。完整写法见原型「规则详情」场景。【已定】

**网站规则只调参数，不重写功能**：

```jsonc
"sites": [
  { "match": ["*://github.com/*"], "for": "official-translate/translate.page",
    "blocks": [".markdown-body p", ".markdown-body li"], "skip": "{{ page.url.contains('/blob/') }}" }
]
```

**规则作用到界面的方式**【已定】：

| 规则里写的 | 界面上出现的 |
|---|---|
| 一个 `feature` | 设置窗口左侧「功能」分组里多一个菜单页 |
| 功能的 `settings` | 菜单页顶部「共用」一组设置 |
| 每个 `entry` | 菜单页里一组：入口开关、「它会做什么」、这个入口自己的设置 |
| 标了 `quick` 的设置、`command` 触发器 | 小猫气泡里的开关、下拉框、按钮；`command` 同时生成快捷键和脚本猫菜单项 |
| `triggers` + `match` | 在哪些网站、由什么动作启动 |
| `present` | 结果出现在哪里、长什么样 |

**代码提供的基础组件**（第一期实现前一组，后一组随网页对照入口一起做）：

| 类别 | 第一期 | 网页对照入口时 |
|---|---|---|
| 触发器 | `selection` | `command`、`page-load` |
| 触发上下文 | `selection.text / lang / sentence / rect`，`page.url / title` | `blocks` |
| 步骤 | `set`、`call`（可流式返回） | `call` 的 `batch: blocks` |
| 页面选取 | — | `select`：`blocks`（选择器或自动识别段落）、`exclude`、`lazy: viewport`、`watch: mutations` |
| 展示位置 | `near-selection`、`bubble` | `inline-after`（插在段落后面，可以隐藏原文）、`toggle` |
| 视图组件 | card、row、text、icon、icon-button、button、select、spacer、dots、`result-list` | 行内译文样式 |
| 动作 | `copy`、`retry`、`rerun`、`open`、`surface: pin / close` | — |
| 设置类型 | boolean、enum、language、engine、engines、string、number | hotkey |

**相关规矩**【建议】：

- **「它会做什么」从规则自动生成**：根据 `match`、`triggers`、`select`、`run`、`present` 写成大白话，启用前可以看清楚。
- **设置值属于你**：
  - 存储时按"规则包 + 功能 + 入口 + 设置项"区分，`scope: "site"` 的再按网站区分；
  - 规则更新后，设置值保留，新增的设置项用默认值，删掉的清除，类型变了恢复默认值。
- **卡片里临时换语言**（`rerun`）只对这一次有效，不改你的设置。
- **行内译文的隔离**：插进网页的译文用自带 Shadow DOM 的自定义元素，不受网页样式影响，也不影响网页。

## 8. 契约

内置三个最基础的契约，它们只是官方规则包预先带上的，和以后新增的契约用同一套机制：【已定】

| 契约 | 输入 | 输出 | 典型用途 |
|---|---|---|---|
| `translate` | `texts[]`、`from`、`to`、`context`（可选） | `texts[]` | 划词翻译、网页对照翻译 |
| `chat` | `messages` | `text` | 生成、总结、解释 |
| `choose` | `state`、`question`、`options` | `choice`、`confidence` | 选择题、"哪个是跳过广告按钮"、是/否判断、打分 |

规则包可以声明新契约，例如：

```jsonc
{
  "id": "weather/current@1",
  "description": "查询某地当前天气",
  "input":  { "type": "object", "properties": { "location": { "type": "string" } }, "required": ["location"] },
  "output": { "type": "object", "properties": { "temp": { "type": "number" }, "condition": { "type": "string" } } },
  "bridgeable": false,
  "sample": { "location": "杭州" },
  "view": { "type": "card", "children": [ { "type": "metric", "value": "{{output.temp}}", "unit": "°C" } ] }
}
```

**契约的规矩**【建议】：

- **命名空间和大版本号**：例如 `weather/current@1`。同一个大版本内只能增加可选字段；要做不兼容的改动，就发新的大版本。
- **同名冲突**：两个规则包声明了同一个 id 但内容不同时，以优先级高的为准，界面上标出"有冲突"。官方包的契约不能被覆盖。
- **`bridgeable`**：能否用大模型兜底。天气、汇率这类需要实时数据的契约设为 `false`。
- **`sample`**：样例输入。任何引擎的「测试」按钮都用它试调一次，并检查返回格式。
- **`view`**：默认的结果视图，见第 12 节。

## 9. 引擎：契约的实现

**一个引擎由四部分组成**【已定】：

```jsonc
{
  "id": "…", "name": "…", "extends": "…", "abstract": false,
  "secrets": [ … ],    // ① 需要哪些 Key（名称、标题、去哪申请）
  "options": { … },    // ② 可调参数的声明（类型、标题、默认值），引擎详情的「模型与参数」据此自动生成
  "hosts":   [ … ],    // ③ 会访问哪些域名：域名确认以它为准，不在列表里的请求一律拒绝
  "limits":  { … },    //    超时、重试、并发、每分钟次数
  "implements": {      // ④ 实现了哪些契约，每个用下面三种方式之一
    "<契约>": { "http": … } | { "via": … } | { "builtin": … }
  }
}
```

**三种实现方式**【已定】，按这个顺序优先选用：

1. **`http`：声明式多步请求**，覆盖几乎所有服务：
   - `steps`：前置步骤，比如先取 token，结果可以缓存一段时间；
   - `request`：method、url、headers，请求体可以是 json / form / text；
   - `stream`：流式响应（SSE）的格式、增量字段、结束标志；
   - `output`：把响应映射成契约的输出；
   - `errors`：按状态码或响应内容识别错误类型（Key 有问题、太频繁、服务端错误……），并给出提示文字；
   - `batch`：多条输入怎么拆分、合并；`langMap`：语言代码怎么转换。
2. **`via`：把一个契约转成对另一个契约的调用**。"大模型桥接"就是 `via chat` 加一段提示词，再加上 `check` 检查输出（不通过就带着错误重试一次）。桥接本身也是规则，比如官方的 `llm-translate`、`llm-choose`。
3. **`builtin`：代码里的适配器**，只给声明式写不出来的情况用（比如 WebSocket、二进制协议）。第一期不需要。

**官方引擎全部写成规则**【已定】：
- OpenAI 兼容是一个抽象引擎（`abstract: true`），支持 Chat Completions 和 Responses 两种接口；DeepSeek、GLM、通义、OpenAI 都继承它；
- Google、微软翻译是 `http` 实现；微软要先取 token，用 `steps` 完成；
- Jev 是一条 `POST https://api.typesafe.ai/v1/systemone` 的 `http` 实现，可以随第一期的官方规则一起提供。它目前还在早期体验阶段，需要申请。

**试运行**【已定】：引擎详情里提供「试运行」，用契约的 `sample` 调用一次，逐步展示每个步骤：桥接、请求（Key 打码）、响应、每个表达式算出的值、最终输出、耗时。规则作者主要靠它调试。

**以后可能增加**【待定】：「MCP 服务器」引擎类型。

## 10. 表达式与依赖库

**表达式语言：CEL**【已定】

- 规则里 `{{ … }}` 中的内容按 CEL（Common Expression Language）求值。可以用常见运算符（`==`、`&&`、`||`、`!`、`? :`、`+`、`in`），有边界的集合操作（`map`、`filter`、`exists`），以及白名单函数；没有循环和副作用。
- **白名单函数**：
  - 字符串：concat、replace、split、join、contains……
  - 编码：urlencode、base64、hex
  - 哈希：md5、sha256、hmacSha256
  - 时间：now、unix
  - 随机：uuid、random
  - JSON：json、extractJson
  - 语言：langName、languages、lang（按 `langMap` 转换）
  - 其他：host、has、size
- **模板规则**：字符串**整段**就是一个 `{{ }}` 时，返回原始值（可以是数组、对象）；里面夹着其他文字时，按字符串拼接。
- **可用的变量**：`settings`、`vars`、`input`、`secret`、`options`、`selection`、`page`、`site`、`steps`、`response`、`stream`、`result`、`item`、`params`。`let` 是 CEL 的保留字，所以变量统一叫 `vars`。
- **限制**：语法树节点数、嵌套深度、列表长度都有上限；保存规则时做语法检查，错误定位到具体字段。

**依赖库**【已定；大小是 2026-11-16 实测的压缩后 / gzip】

| 用途 | 库 | 大小 | 说明 |
|---|---|---|---|
| 表达式 | @marcbachmann/cel-js 8.x（MIT，无依赖） | 82 KB / 23.8 KB | 不用 `eval`，网站开了严格 CSP 也能用；报错带位置；整数默认是 BigInt，要在边界处统一转成普通数字 |
| JSON Schema 校验（规则、契约输入输出） | @cfworker/json-schema | 22.6 KB / 6.4 KB | 不用 `new Function`。ajv 会用 `new Function`，而且大很多，不用 |
| 流式响应解析 | eventsource-parser | 4.4 KB / 1.8 KB | |
| md5 | js-md5 | 10 KB / 3.5 KB | sha256、hmac、uuid 用浏览器自带的 WebCrypto |
| 界面 | React + Radix 无样式原语 + Tailwind 4 | — | 和原型同一套技术 |

不用的：filtrex、expr-eval（用了 `new Function`）、@bufbuild/cel（278 KB，还是 Beta）。

## 11. 调用管道与路由策略

**每次调用都经过同一条管道**【已定】，每一步是独立的中间件。新接入的引擎自动具备这些能力，不用重复实现：

```
校验输入 → 隐私和授权检查 → 缓存 → 选择实现 → 限速和预算 → 执行（超时、重试）
→ 校验输出 → 统一置信度 → 记录用量和日志 → 返回结果
```

**路由策略由调用方指定**【已定】：

| 策略 | 含义 | 典型场景 |
|---|---|---|
| `first` | 按优先级用第一个，失败换下一个 | 默认 |
| `race` | 同时请求，用最快返回的 | 对速度敏感的自动化 |
| `all` | 全部并行，结果都返回 | 划词卡片同时显示多个引擎 |
| `vote` | 多个实现投票，一致程度作为置信度 | 做题时多个引擎互相印证 |

**置信度的三种来源**：引擎自带（如 Jev）、投票得出、没有。【已定】

## 12. 结果的展示：组件渲染

**第一层：声明式组件**【已定，A】

- 规则只描述"摆什么组件、绑定什么数据"，由陪伴猫用自己的组件库渲染。思路和 Adaptive Cards、A2UI 一致。
- **组件集合小而固定**：卡片、行/列、文本、Markdown（经过净化）、数值、徽章、列表、键值表、图片（受域名策略限制）、进度条、按钮组。
- **数据绑定**：用第 10 节的 CEL 表达式，可以用 `input`、`output`、`meta` 等变量。
- **按钮能做的事只有这几种**：`call`（再调用一个契约）、`copy`（复制）、`open`（打开链接，要经过域名检查）、`fill`（填进页面，只在网站规则里可用）。
- **没写 `view` 时**：按输出格式自动生成。字符串显示为文本，对象显示为键值表，数组显示为列表。
- **为什么选这一层做默认**：不受网页 CSP 影响，风格、深色模式、窄屏、无障碍都统一，也不执行规则作者的代码。

**第二层：沙箱应用**【已定方向，以后再做】

- 协议兼容 MCP Apps：用 `ui://` 资源，postMessage 加 JSON-RPC 通信，事先声明 CSP。
- 安装时单独征得你同意。
- 网页 CSP 不允许嵌入时，改在脚本猫的独立页面里打开，或者退回声明式视图。

**和功能界面的关系**：功能的界面（比如划词卡片）同样用声明式组件拼成，再写成视图模板供复用。只有确实需要专门交互的组件（比如 `result-list`、行内译文）才由代码提供，但它们也是规则里可以直接使用的组件。

## 13. 安全与隐私

- **Key 的存储**【建议】：用脚本自带的存储明文保存，在脚本猫的「存储」面板里能看到。不加主密码。
- **Key 的绑定**【已定】：按"引擎 + 请求域名"绑定。规则更新后域名变了，弹窗确认；拒绝后停用这个引擎。
- **继承的引擎共用 Key**【已定】：用 `extends` 继承的引擎，默认使用父引擎的 Key。
- **发送内容要告知**【已定】：网站规则会把页面内容发给外部服务（Jev 或大模型），所以每条这样的规则都要你单独开启。开启时写明会发送什么内容、发到哪个域名。
- **日志脱敏**【建议】：日志和导出的数据里不出现 Key。
- **自动化限速**【建议】：每条规则都有动作频率上限，防止失控连点。

## 14. 交互与视觉

- **两层交互**【已定】：
  - **日常**：点角落的小猫，弹出对话气泡。可以开关这个网站的划词、切换引擎和目标语言、看到"还有几个引擎没填 Key"、看到这个网站生效的规则（第二期起）。
  - **配置**：设置窗口。左侧导航分两组：上面「功能」是规则提供的功能页（比如划词翻译），下面「陪伴猫」是外壳自带的「引擎」「规则」「通用」。引擎页左边是列表、右边是详情，可以一个接一个连续填 Key。「通用」里只有外壳自己的设置：每种能力先用哪个引擎、角落里的小猫、外观、缓存。
  - **没有规则时**：左侧「功能」分组是空的，引擎页和小猫气泡都会引导你去订阅官方规则。
- **划词**【已定】：选中文字后先伸出一只猫爪，点了才翻译。结果卡片的形状像对话气泡；默认引擎的译文用宋体大字作为主结果，其他引擎显示在下面。
- **视觉**【已定】：「猫毛色」配色。
  - 白毛色用于内容表面，橘色用于主操作，三花黑斑色用于墨色、选中状态和卡通描边；
  - 背景是中性的浅灰，不用奶油色；
  - 同一套配色要同时适配橘猫和三花两种花色；
  - 界面字体用系统圆体，译文用宋体；
  - 浮在网页上的元素都有 1.5px 卡通描边。
- **草图**：`.dev-kit/artifacts/2026-11-16-core-and-selection/mockups/`（v4）。实现时以草图的界面和交互为准；Shadow DOM 里的弹出层挂载、`:host`、rem 换 px 这三件事要额外处理。

## 15. 路线图

| 期 | 内容 | 说明 |
|---|---|---|
| 1 | **能力引擎核心 + 规则驱动的功能 + 划词翻译** | 引擎层：契约（内置三个）、实现（`http` / `via`，`builtin` 只留接口）、调用管道、四种路由策略、统一结果。规则层：订阅、合并、继承、覆盖。Key 和域名确认。外壳：小猫、气泡、设置窗口和自带的三页。功能运行时：设置类型和自动生成的设置页、`quick` 气泡开关、`selection` 触发器、`near-selection` 展示位置、`result-list` 等基础视图组件。「翻译」功能的划词入口完全用规则实现（含视图模板 `translation-card`），作为对这一整套的验证；官方引擎（含 Jev）全部写成规则；表达式用 CEL；引擎详情提供试运行。规则格式里给 `sites` 和 `view` 预留位置，并发布一份机器可读的规则 JSON Schema，给本地规则编辑器的校验用，也给第二期的 AI 写规则用 |
| 2 | 网站规则与页面自动化 + 接入 Jev + 用 AI 写规则 | 动作执行器（点击、填写、等待等），带"问引擎"的决策步骤，置信度门槛和"先问你"的交互；第一个用例是跳过广告。用 AI 写规则：你用一句话描述想让小猫做的事，并在页面上点选相关元素；陪伴猫用你自己配好的 `chat` 引擎，按规则 JSON Schema 生成规则草稿，用同一个校验器检查，不合格就把错误交回给 AI 修改；然后在当前页面试运行（高亮命中的元素，展示会发送什么），确认后存进本地规则。生成的规则依然只是 JSON，同样要经过启用前的确认 |
| 3 | 填充做题 | 题目提取、选择题用 `choose`（Jev / 大模型 / 投票）、填空题用 `chat` 或规则声明的契约；用第二期的动作把答案填进页面，不自动提交 |
| 4 | 「翻译」的网页对照入口 | 加入 `command`、`page-load` 触发器，`select` 段落选取，`inline-after` 展示位置，`batch: blocks`；规则格式在第一期已经定好 |
| 以后 | 通用能力入口、声明式组件库、沙箱应用、MCP 引擎、对外接口 | 按需要排期 |

## 16. 决策记录

| 决定 | 理由 | 放弃的方案 |
|---|---|---|
| 规则只用 JSON 声明 | 安全，不受网页 CSP 影响 | 允许 JS 钩子（订阅等于运行别人的代码）；规则就是 JS 模块（风险和维护成本最高） |
| 以能力引擎为核心 | 新场景最好只写规则就能加，竞争力在引擎层 | 以规则执行引擎为核心；两层同时做（第一期范围太大） |
| 开放契约 | 加天气、笑话这类能力不用改代码，所有能力共用安全和可靠性机制 | 固定的几种能力（扩展要发新版本） |
| 声明式组件优先，以后兼容 MCP Apps | 风格统一，不受 CSP 影响，不执行规则作者的代码 | 一开始就用 HTML 沙箱（受 CSP 限制、外观不统一）；永远只用声明式（复杂界面做不了） |
| 首次安装就订阅官方大模型包 | 装上就能看到可以用的大模型 | 让用户自己手动订阅 |
| OpenAI 兼容同时支持 Chat 和 Responses 两种接口 | 用户要求 | 只支持 Chat |
| 表达式用 CEL（@marcbachmann/cel-js） | 标准语法、可读，没有副作用，不用 eval；Go 服务端也能用 cel-go 校验 | 只能嵌套函数（难读）；自创文本 DSL（工具和 AI 支持差）；jexl、subscript（语法不标准） |
| 引擎全部写成规则（http / via / builtin） | 签名、取 token、流式响应都能声明式写出，接新服务不用发版 | 内置适配器写在代码里（每接一个这类服务都要发版） |
| 功能分成多个入口、共用设置 | 「翻译」一个功能同时有划词和网页对照，共用目标语言 | 每种用法一个独立功能（设置重复） |
| 结果卡片用视图模板描述 | 和"功能都来自规则"一致，社区可以做不同样式 | 把卡片做成代码里的大组件 |
| 功能由规则声明，外壳只提供基础组件 | 划词翻译、设置项、菜单、气泡开关都能靠规则增加，和"能力是开放的"同一个思路 | 功能写死在代码里，规则只管引擎 |
| 陪伴猫有自己的视觉风格（猫毛色） | 用户要求和 ScriptCat 区分；猫会是橘猫或三花 | 沿用 ScriptCat 风格；猫薄荷绿配色 |
| 日常和配置分成两层交互 | 每次划词前要改的东西一步就能改，配置时可以连续操作 | 一个侧边面板装下所有东西 |
