# 陪伴猫第二轮：页面自动化 + 做题 + 用 AI 写规则 + 网页对照

> Status: Approved
> Owner: 陪伴猫项目维护者
> Last updated: 2026-11-17

**Objective:**

- 陪伴猫能按规则在网页上动手：
  - 点击、填写，并在需要时先问引擎再决定；
  - 没把握时先问你。
- 在此基础上交付三项能力：
  - 官方的「跳过广告」和「做题」；
  - 通过和小猫对话写出、并持续修改一条自动化规则；
  - 「翻译」的网页对照入口。

**Hard invariant:**

1. 规则仍然只是 JSON 加受限的 CEL 表达式，任何规则内容都不会被当作 JS 执行。
2. API Key 只会发往该引擎已确认过的域名（沿用一期 R7.4、R7.5）。
3. 订阅来的规则不会在你不知情的情况下动手：自动化入口默认关闭，打开前要你确认；每次动作都有记录；每个网站都能一键暂停。
4. 陪伴猫自己插入的元素都在 Shadow DOM 里，不改变宿主网页的样式。会改变网页的只有两种情况：
   - 你打开的自动化动作；
   - 你开启的网页对照。

## Problem

1. **陪伴猫现在只会划词翻译。**
   - 【已验证】main（be478d8）上的功能运行时只支持 `selection` 触发器、`set`/`call` 步骤和 `near-selection` 展示位置。
   - 【已验证】规则里出现 `entries.page` 时，入口显示为「这个版本的陪伴猫还不支持这个入口」（一期 R10.8，运行验证通过）。
   - 结果：产品方向里的「跳过广告、做题、自动操作网页」都还做不到。
2. **一期的表达式不能读网页。**
   - 【已验证】一期 R8.1 规定「不提供任何能访问 DOM、网络或存储的函数」。
   - 自动化必须能找到元素、读到元素的文字，否则规则无法描述「点哪个按钮」。
3. **规则只能手写。** 【用户已定】要让普通用户用一句话描述，由陪伴猫借助用户自己的对话引擎写出规则。
4. **「翻译」只做了一半。** 【已验证】网页对照入口的规则格式在一期已经定好（产品方向 §7），但没有实现。

## Actors and user stories

1. 作为**普通用户**，我想打开「跳过广告」后，视频网站上一出现「跳过广告」按钮小猫就帮我点掉；没把握时先问我，这样我不用盯着倒计时。
2. 作为**学生**，我想在练习页上点一下「帮我做这页的题」，小猫把有把握的答案填好，没把握的标出建议答案，并且不替我交卷，这样我能自己检查后再提交。
3. 作为**普通用户**，我想像聊天一样告诉小猫想让它做什么：它不确定时会问我，我可以在页面上点一下相关的元素，也可以随时用一句话纠正；每一版我都能看到它会做什么、会把什么发给谁；保存之后还能接着和它改。
4. 作为**普通用户**，我想一键把整个网页翻译成「原文 + 译文」对照，滚动到哪里翻到哪里，再按一次就恢复原样。
5. 作为**普通用户**，我想随时知道小猫在这个网站上做过什么，并能一键让它停手。
6. 作为**规则作者**，我想用同一套规则格式写网站自动化：
   - 触发、找元素、问引擎、动手、判断；
   - 并用一期的校验器和试运行调试。

## 1. 自动化的规则写法

- **R1.1 触发器**：
  - `page-load`：页面加载完成后运行一次。`enabled` 为假时不运行。
  - `appear`：页面上新出现匹配 `selector` 的元素时运行。
    - 页面加载时已经存在的元素不算新出现。
    - 有去抖：同一批变化在 `debounceMs`（默认 300）内只触发一次。
    - `trigger.element` 是新出现的那个元素。
  - `command`：
    - 生成一个气泡按钮；写了 `hotkey` 时还生成快捷键；同时生成一个脚本猫菜单项。
    - 用户点按钮、按快捷键或点菜单项时运行。
    - `title` 是按钮文字。
- **R1.2 步骤**（在一期 `set`、`call` 的基础上新增）：
  - `find`：在页面上（或 `within` 指定的范围里）找元素。
    - 用 CSS 选择器筛选，可以再用 `where` 表达式按元素过滤，`all: true` 时返回全部。
    - 结果存进 `vars.<as>`，是元素句柄的列表。
    - 只返回可见的元素。
  - `act`：对目标元素做一个动作。
    - `click`：点击。
    - `fill`：填入文字，会像真实输入一样触发网页的 input/change 事件。
    - `check`：勾选或取消勾选。
    - `select`：在下拉框里选中一项。
    - `scroll`：滚动到元素。
    - `focus`：让元素获得焦点。
    - `wait`：等待若干毫秒，或等到某个选择器出现，有超时。
  - `ask`：调用一个契约，通常是 `choose` 或 `chat`。
    - 可以写 `engine`、`strategy`、`input`、`as`。
    - 结果带 `confidence`。
    - 走一期的调用管道：缓存、错误类型、域名确认都照旧。
  - `if`：条件为真时执行 `then`，否则执行 `else`（可选）。
  - `repeat`：对一个列表的每一项执行，当前项是 `item`；或者重复执行，直到条件成立，最多 `max` 次。
  - `stop`：结束这次运行。
- **R1.3 门槛**：
  - `act` 可以带 `confidence`（通常取 `ask` 的结果）和 `minConfidence`。
  - 达到门槛就直接执行。
  - 低于门槛时按 `below` 处理：
    - `ask`：先问你，见 R2.1。
    - `hint`：在目标旁边标出建议，不动手。
    - `skip`：什么都不做，只写进动作记录。
  - 没写 `minConfidence` 的 `act` 直接执行。
- **R1.4 页面函数**（只读，只能在自动化入口的 `triggers`、`run` 里用；在其他位置用了按语法错误处理）：
  - `text(el)`：元素的可见文字。
  - `attr(el, name)`：元素的属性值。
  - `describe(el)`：给人看的一句描述，例如「「跳过广告」按钮」，用于动作记录和问引擎。
  - `outline(el, n)`：元素及其周围不超过 n 个字的精简结构。
    - 包括标签、文字、少量属性。
    - **不含**输入框里的值。
  - `closest(el, selector)`：最近的匹配祖先。
  - `within(el, selector)`：元素内部的匹配后代。
  - `visible(el)`：元素是否可见。

  元素句柄只能传给这些函数和 `act`，不能被转换成任何能执行的东西。
- **R1.5 「它会做什么」**：
  - 一期 R9.2 的大白话生成要覆盖新的触发器和步骤。例如：
    - 「新出现跳过按钮时」
    - 「问 DeepSeek 哪个是跳过按钮」
    - 「把握 85% 以上就点，没到就先问你」
  - 每句下面标出来自规则的哪个字段。
  - 会把页面内容发给引擎的步骤，单独写明发送什么、发到哪个域名。
- **R1.6 失败处理**：
  - `find` 没找到：结果是空列表，不报错。
  - `ask` 失败：
    - 按一期的错误类型，在动作记录里写原因；
    - 停止这次运行，不执行后面的动作。
  - `act` 的目标已经不在页面上：
    - 跳过这个动作，记录「目标已经不在了」；
    - 继续执行后面的步骤。
  - `wait` 超时：停止这次运行并记录。
  - 页面跳转或刷新：未完成的运行直接丢弃，不在新页面上继续。
  - 同一个入口上一次还没运行完时又被触发：丢弃这次触发。
- **R1.7 表达式和校验**：新的触发器、步骤、页面函数都进入一期的规则 JSON Schema 和本地规则编辑器的校验，错误同样带行号、字段路径和表达式位置。

## 2. 先问你和执行反馈

- **R2.1 先问你**：低于门槛且 `below` 为 `ask` 时：
  - 动作暂停，在目标元素旁边弹出小气泡：
    - 「小猫觉得是这个按钮（72%），要点吗？」
    - 一行小字说明哪条规则、哪个引擎判断的、门槛是多少；
    - 两个按钮：「点吧」「不用」；
    - 一个勾选框：「这个网站以后都照做」。
  - 目标元素加上一圈虚线框；角落的小猫睁眼，并显示「等你回答」。
  - 「点吧」：执行动作。
  - 「不用」：不执行，记录。
  - 30 秒没有回答、目标元素消失、或者页面跳走：当作「不用」。
- **R2.2 自动执行的提示**：达到门槛直接执行后：
  - 小猫旁边出现几秒提示：「小猫帮你点了「跳过广告」（93%）」，附「撤销」「记录」两个链接；
  - 被点的元素短暂高亮。
- **R2.3 这个网站以后都照做**【用户已定】：
  - 勾选后，这条规则在这个网站上低于门槛也直接执行，不再问。
  - 只保存成你这台电脑上的网站级设置，不修改规则。
  - 可以在功能页里撤销。
- **R2.4 撤销**【用户已定】：
  - `click`、`check`、`select`、`scroll`、`focus`、`wait` 没法真正撤销，「撤销」的作用是：
    - 把这次动作标记为「点错了」；
    - 把这条规则在这个网站上切回「先问你」。
  - `fill` 的「撤销」会把输入框恢复成原来的值。

## 3. 开关、暂停、记录

- **R3.1 默认关闭**：订阅来的规则包里，自动化入口（含 `act` 或会发送页面内容的 `ask` 的入口）默认关闭。
- **R3.2 启用确认**：在功能页或气泡里第一次打开订阅来的自动化入口时，弹出确认框，写明：
  - 会做的动作：从规则的 `act` 步骤汇总；
  - 会发出去的内容和地址：从 `ask` 步骤和所选引擎算出；
  - 在哪里生效：`match`，以及是否要按网站单独打开；
  - 来自哪个规则包、哪个版本。

  两个按钮：「先不打开」「打开」。点「打开」后才生效。
- **R3.3 更新后再确认**【本规格提议】：
  - 已打开的自动化入口，在规则包更新后，如果动作种类或发送地址变了，就自动暂停。
  - 下一次触发时，按 R3.2 再确认一次。
  - 只改了文字、门槛等其他内容时不打扰。
- **R3.4 本地规则**【用户已定】：
  - 你自己写的或 AI 写的本地规则，保存后自动化入口就是打开的，不弹启用确认。
  - 但同样出现在动作记录里，也同样受暂停控制。
- **R3.5 网页对照不算自动化**【用户已定】：它不点击、不填写，入口默认打开；按网站自动对照默认关闭。
- **R3.6 气泡里的「自动化」**：在有自动化规则生效的网站上，点小猫，气泡里多出一组：
  - 这个网站上生效的自动化入口。
    - 每项有名称、一句话说明，以及开关或「命令」标记。
    - 按网站打开的入口，开关就是它的站点设置。
  - 「在这个网站暂停自动化」：
    - 打开后，这个网站上所有自动化都不运行，命令按钮变灰；
    - 规则和开关不变；
    - 再关掉就恢复。
  - 最近动作：本网站最近 20 条。
    - 每条有时间、动作和目标描述（`describe`）、规则名、执行方式（自动 / 问过你 / 不是广告 / 没点）、置信度。
    - 点「全部」打开完整记录。
- **R3.7 动作记录**：
  - 每条记录包括：时间、网站、规则和入口、动作、目标描述、置信度、执行方式、失败原因。
  - 只存在本机，每个网站保留最近 20 条。
  - 记录里不出现 Key，也不出现 `fill` 填入的内容。

## 4. 官方「跳过广告」

- **R4.1 写法**：
  - 一个功能，对所有网站生效（`match: *://*/*`），一个入口「自动跳过广告」。
  - 入口设置：
    - 「在这个网站跳过广告」（按网站，默认关，放进气泡）；
    - 「用哪个引擎判断」（`choose` 引擎）；
    - 「多有把握才直接点」（默认 85%）；
    - 「低于门槛时」（先问你 / 只提示 / 不做，默认先问你）。
- **R4.2 行为**：
  - 前提：在某个网站上打开了这个入口。
  - 动作：页面上新出现按钮或链接，且文字像「跳过 / Skip / 关闭广告」。
  - 结果：
    - 把候选按钮的描述和周围约 400 字的结构发给 `choose` 引擎，问「哪个是跳过或关闭广告的按钮」，选项包括「都不是」。
    - 引擎选中某个按钮，且达到门槛：点击它。
    - 选中但低于门槛：按设置处理。
    - 引擎选「都不是」：不点，记录。
- **R4.3 页面已有的按钮不管**【用户已定】：只看新出现的按钮，页面加载时就有的不算。

## 5. 官方「做题」

- **R5.1 写法**：
  - 一个功能，对所有网站生效，一个命令入口「帮我做这页的题」（`command`，放进气泡）。
  - 入口设置：
    - 「选择题用哪个引擎」（不选就用「通用」里「选择和判断」先用的引擎）；
    - 「多个引擎投票」（默认关）；
    - 「填空题用哪个引擎」（`chat`）；
    - 「多有把握才直接填」（默认 80%）；
    - 「低于门槛时」（标出建议答案 / 空着不管）。
- **R5.2 题目识别**：`auto:questions` 找出这一页的：
  - 单选题：同名 radio 组；
  - 多选题：同名 checkbox 组；
  - 填空题：题干附近的文本框。

  每题的题干取题号和选项前面的文字。识别不到题目时，提示「这一页没找到题目」。
- **R5.3 回答**【用户已定：低于门槛只有两种做法】：
  - 选择题：问 `choose`。打开投票时用 `vote` 策略同时问几个引擎。
  - 填空题：问 `chat`，把握取模型自己给出的估计。
  - 达到门槛：勾选或填入答案，题目旁边标「小猫填的 96%」。
  - 低于门槛：
    - 「标出建议答案」：题目上方出现「小猫建议 B（61%），没到门槛 80%，没替你选」，附「就选 B」「我自己来」；
    - 「空着不管」：只在结果卡片里列出。
- **R5.4 不提交**：官方规则里没有点击「提交」的步骤。这是规则自己的写法，不是代码的限制。
- **R5.5 做题结果**：
  - 页面上出现「做题结果」卡片。
    - 列出每题的答案、置信度、引擎；
    - 没到门槛的题单独标出；
    - 点一项滚动到那道题。
  - 卡片底部写明「没有点提交，检查后自己交卷」。
  - 卡片来自规则里的视图模板（`views.quiz-result`）。
- **R5.6 失败**：
  - 某道题的引擎调用失败：
    - 这道题在卡片里显示错误和「重试」；
    - 其他题不受影响。

## 6. 用 AI 写规则（多轮对话）

- **R6.1 入口**：以下三处打开同一个「教小猫做件事」面板：
  - 气泡里的「教小猫做件事」；
  - 「规则」页里的「让小猫写一条规则」；
  - AI 写的规则的功能页里的「继续和小猫改」（见 R6.8）。

  面板左边是对话，右边是当前草稿。
- **R6.2 第一次使用**：
  - 第一次对话的开头提示一次：每轮会把对话内容、你点选的元素的精简结构（`outline`，不含输入框的值）、当前页面的网址和标题、当前草稿、规则 Schema 和一个范例，发给你的 `chat` 引擎，并写明它的域名。
  - 还没有可用的 `chat` 引擎时，引导去引擎页填 Key。
- **R6.3 对话**：你用一句话描述要做的事，之后可以随时补充或纠正，例如「只点正文那个」「没把握就先问我」。小猫的每次回复是以下三种之一：
  - 一个追问：例如「只在 news.example.cn，还是所有新闻网站？」，这时还不出草稿；能选的问题附带快捷回答按钮，点一下就发出去，也可以自己打字；
  - 一版新草稿；
  - 一版新草稿加一个追问。

  生成中可以点「停下」，这一轮就作废，草稿保持上一版。
- **R6.4 点选元素**：
  - 输入框旁边有「点选元素」；小猫也可以在回复里请你点选，回复里带一个「去点选」按钮。
  - 点选模式：
    - 顶部提示「点选相关元素，按 Esc 完成」；
    - 鼠标经过的元素出现高亮框，点一下选中；
    - 点选模式下，点击不会触发网页原来的行为。
  - 选中的元素作为附件挂在你正在写的这条消息上，发送前可以删掉。
  - 小猫不会自己读网页，只看到你点选的元素和页面的网址、标题。
- **R6.5 每一版草稿都会自动检查和试运行**：
  1. **校验**：用一期的同一个校验器检查草稿。不通过时，把错误（字段路径和原因）交回给 AI 重写，最多 3 轮。这一轮的对话里只显示一行结果，例如「校验发现 2 处问题，已修好」。
  2. **试运行**：校验通过后，在当前页面运行一遍，但不执行任何 `act`，也不调用 `ask` 的引擎【用户已定】。网页上用字母标出 `find` 找到的元素。
  3. **右边的草稿区**显示：
     - 「草稿 vN」；
     - 「它会做什么」，带字段来源，和上一版相比新增、删掉、改动的句子分别标出；
     - 每一步会做什么，会发送什么内容、发到哪里。
  4. 3 轮返修后仍不通过：
     - 对话里列出剩下的错误（字段路径和原因）；
     - 提供「让小猫再试」和「自己改」（打开本地规则编辑器，草稿放在里面，未保存）；
     - 草稿区保持上一版能用的草稿。
- **R6.6 版本**：
  - 每一版草稿都保留，可以在 v1、v2、v3…之间切换。
  - 切回旧版后再继续对话，就以它为基础；这时保存，存的就是正在看的这一版。
- **R6.7 保存**：
  - 当前草稿通过校验时，「存进本地规则」可用；不通过时按钮不可用，并写明原因。
  - 第一次保存：作为一个新功能追加到本地规则里，按 R3.4 直接生效；新功能出现在设置窗口左侧「功能」里。
  - 已有的其他规则一个字也不改。
- **R6.8 对话和规则一起保存，之后能接着改**【用户已定】：
  - 对话记录（含点选附件的精简结构和各版草稿）和这条规则一起存在本机。
  - AI 写的规则的功能页有「继续和小猫改」：打开面板，显示原来的对话，可以接着说。
  - 再次保存时只覆盖这一条规则，其他规则不受影响。
  - 在本地规则编辑器里手改过这条规则后，再「继续和小猫改」时，以你手改后的版本作为当前草稿。
  - 删除这条规则时，对话一起删除。
- **R6.9 没保存的对话**：
  - 面板关闭前，如果有没保存的草稿，先问「要丢掉这次的草稿吗」。
  - 页面意外刷新或关闭后，小猫旁边出现一条「接着上次没写完的」，点开就回到那次对话，也可以丢掉。
- **R6.10 窄屏**：面板占满屏幕，用「对话」「草稿 vN」两个标签切换左右两部分。
- **R6.11 失败**：AI 调用失败时：
  - 按一期的错误类型在对话里提示，可以重试这一轮；
  - 之前的对话和草稿不受影响。

## 7. 「翻译」的网页对照入口

- **R7.1 入口生效**：
  - 一期 R10.8 的「还不支持」提示去掉。
  - 「网页对照翻译」入口按产品方向 §7 的规则写法生效。
  - 入口设置：
    - 「用哪个引擎」（单选）；
    - 「显示方式」（原文下面显示译文 / 只看译文，放进气泡）；
    - 「打开这个网站时自动对照」（按网站，默认关）；
    - 「快捷键」（新的设置类型 `hotkey`，默认 Alt+A）。
- **R7.2 打开和收回**：
  - 用以下任一方式打开对照：
    - 气泡里的「对照翻译这个网页」；
    - 快捷键；
    - 脚本猫菜单；
    - 打开了自动对照的网站，页面加载时自动打开。
  - 再执行一次就收回：插入的译文全部移走，被隐藏的原文恢复显示。
- **R7.3 段落选取**：
  - 有网站规则（`sites[].blocks`）时用它的选择器，否则自动识别正文段落。
  - 跳过 `exclude` 里的元素：`pre`、`code`、`nav`、`[translate=no]` 等。
  - 只翻译进入视口的段落。
  - 滚动或页面新增内容时，接着翻译新进入视口的段落。
- **R7.4 翻译和显示**：
  - 用 `batch: blocks` 按条数和字数分批调用 `translate`。
  - 译文插在每段后面：
    - 是一个自带 Shadow DOM 的元素，用宋体，不受网页样式影响；
    - 「只看译文」时隐藏原文。
  - 正在翻译的段落显示占位；翻好的立刻显示，不用等整页翻完。
  - 一期 R6.4 的缓存同样适用。
- **R7.5 失败**：
  - 某一批翻译失败：这批段落后面各显示一个小的「重试」，其他段落不受影响。
  - 引擎没有 Key 或被停用：提示，并给出去引擎页的链接。

## 8. 规则格式、官方规则包和 Schema

- **R8.1 Schema**：一期的规则 JSON Schema 加入：
  - 新的触发器、步骤；
  - `act` 的门槛字段；
  - `select`、`inline-after`、`toggle`；
  - 设置类型 `hotkey`，以及 `number` 的 `format: percent`；
  - 页面函数的使用位置。

  Schema 向后兼容：一期的规则仍然有效。
- **R8.2 官方规则包**：
  - 规则仓库新增「跳过广告」「做题」两个包，「翻译」包的网页对照入口去掉不支持标记。
  - 都要通过 Schema 校验和规则仓库的检查脚本。
  - 并作为范例覆盖以下写法：`appear`、`command`、`find`、`ask`、`act` 的门槛、`repeat`、`if`、`auto:questions`、`batch: blocks`、`inline-after`。
  - 规则仓库的推送要先问用户。
- **R8.3 内置快照和订阅**：按决定 #11：
  - 首次安装默认订阅全部官方包；
  - 已经装过的用户升级后补订新包一次；
  - 用户以前取消订阅过的包不补。

## 9. 兼容、隐私、无障碍、界面状态

- **R9.1 浏览器**：同一期 R13.1（脚本猫，严格 CSP 页面照常工作）。
- **R9.2 隐私**：
  - 自动化和 AI 写规则只发送 R1.5、R3.2、R6.2 写明的内容。
  - AI 写规则的对话记录只存在本机。
  - `outline` 不包含任何输入框的值。
  - 动作记录不包含 `fill` 的内容。
- **R9.3 无障碍**：
  - 「先问你」气泡、启用确认框、写规则面板、做题结果卡片都能用键盘操作。
  - 弹出时焦点进入弹窗，关闭后回到原来的位置。
  - 「先问你」气泡按 Esc 等同「不用」。
- **R9.4 界面状态**：以原型 v6 为准，必须覆盖原型里的这些状态：
  - 跳过广告：先问你、已自动点击；
  - 气泡里的「自动化」分组；
  - 启用确认；
  - 跳过广告功能页；
  - 做题·填好了（含没到门槛的题和结果卡片）；
  - 写规则：对话开始、小猫追问、点选元素、草稿和改动、校验没通过、继续改（功能页和重新打开的对话）；
  - 网页对照：进行中（含加载中和失败重试）、只看译文；
  - 网页对照功能页。

  深色和窄屏同一期 R1.7 和 R1.5。

## Out of scope

- 跨页面的自动化流程：在新页面上接着执行上一页没做完的步骤。（本期页面跳转即丢弃，见 R1.6。）
- 代码层面对动作的限制：拦截提交、密码框、跨站链接，强制限速。【用户已定】不做，见决定 #2。
- 针对具体网站的官方自动化规则：某视频站、某题库。
- AI 修改不是它写的规则（官方规则、手写的本地规则）；AI 直接生成规则包。
- 「撤销」真正撤回一次点击。
- 一期 Out of scope 里的其余事项：
  - 通用能力入口、沙箱应用、MCP 引擎、对外接口；
  - `builtin` 适配器；
  - iframe 内运行；
  - 预算、用量统计；
  - 规则市场；
  - 发布渠道。
