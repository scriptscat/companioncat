# 陪伴猫第一期：能力引擎核心 + 规则驱动的功能 + 划词翻译

> Status: Approved
> Owner: 陪伴猫项目维护者
> Last updated: 2026-11-16

**Objective:** 交付一个能在脚本猫里运行的用户脚本：它本身只是外壳，订阅官方规则后就能划词翻译。引擎、功能、设置项、菜单、气泡开关全部由规则声明，规则作者可以在本地写规则、试运行并调试。

**Hard invariant:**
1. 规则只是 JSON 加受限的 CEL 表达式，任何规则内容都不会被当作 JS 执行。
2. API Key 只会发往该引擎已确认过的域名。
3. 陪伴猫不改变宿主网页原有的样式和行为：只在用户触发的地方插入自己的元素，并且不在输入框里触发划词。

> 标记说明：**【已验证】** 是我在仓库或环境里核实过的事实；**【用户已定】** 是对话中你确认过的决定；**【本规格提议】** 是我提出、随本规格一起等你批准的内容；**【未知】** 是仍待决定的事项，列在「Open questions」里。
>
> 背景、完整的取舍和被否决的方案见 [产品方向](../product-direction.md)。界面以本地原型为准：`.dev-kit/artifacts/2026-11-16-core-and-selection/mockups/`（v5）。原型只是参考依据，有约束力的要求都写在本文里。

## Problem

1. **目前没有任何实现。** 【已验证】`companioncat/` 目录里只有 `docs/` 和 `.dev-kit/`（原型），没有代码，也还不是 git 仓库。
2. **想要的东西现成工具做不到。** 【用户已定】需要一个能力和功能都靠在线规则定义的工具：引擎要同时支持通用 API 和特定 API；规则包之间可以组合、继承；功能、设置项、菜单都由规则提供；以后还要扩展到网站自动化、做题，以及用 AI 写规则。现成的划词翻译脚本，功能和服务商都写死在代码里。
3. **如果第一期把格式定错，后面要推翻重来。** 【用户已定】第二期（网站自动化、Jev、AI 写规则）、第三期（做题）、第四期（网页对照入口）都要建立在第一期定下的规则格式、引擎层和功能运行时之上。

## Actors and user stories

1. 作为**普通用户**，我想装上脚本就能在任何网页上选中文字、看到翻译，这样读外文时不用切换页面。
2. 作为**普通用户**，我想按引导给大模型填好 API Key，并能放心 Key 不会被发到我不认识的地方，这样我才敢用付费的引擎。
3. 作为**普通用户**，我想在每个网站上单独关掉划词或隐藏小猫，这样它不会打扰我。
4. 作为**规则作者**，我想只写 JSON 规则就接入一个新的翻译服务（包括需要签名或先取 token 的服务），用试运行看清每一步，这样不用等陪伴猫发新版本。
5. 作为**规则作者**，我想在本地规则里改官方引擎的参数、继承官方引擎新建一个引擎、针对某个网站调整功能，并且这些修改在官方规则更新后依然保留。
6. 作为**官方规则维护者**，我想把「翻译」功能和常见大模型写成两个官方规则包，并有一份 JSON Schema 校验它们，这样官方包本身就能作为范例。

## Design decisions

| # | 决定 | 依据和放弃的方案 |
|---|---|---|
| 1 | 陪伴猫是外壳，功能、设置项、菜单、气泡开关由规则声明 | 【用户已定】放弃：功能写死在代码里，规则只管引擎 |
| 2 | 规则是 JSON + CEL 表达式，表达式只能调用白名单里的纯函数 | 【用户已定】放弃：允许 JS 钩子；规则就是 JS 模块；自创文本 DSL；表达式只能嵌套函数 |
| 3 | 以能力引擎为核心：契约（开放）→ 实现 → 调用管道 → 路由策略 → 统一结果 | 【用户已定】放弃：固定的几种能力；以规则执行引擎为核心 |
| 4 | 引擎实现方式按优先级：`http`（声明式多步请求）、`via`（转成调用另一个契约）、`builtin`（只留接口） | 【用户已定】放弃：签名、取 token 类服务写成代码里的适配器 |
| 5 | 功能 → 多个入口 → 共用设置；第一期只实现「翻译」的划词入口，但格式按两个入口来定 | 【用户已定】放弃：每种用法一个独立功能 |
| 6 | 结果卡片由声明式组件拼成，写成规则里的视图模板 `translation-card` | 【用户已定】放弃：卡片做成代码里的大组件；每个功能复制一份卡片 |
| 7 | 依赖库：@marcbachmann/cel-js、@cfworker/json-schema、eventsource-parser、js-md5；界面用 React + Radix + Tailwind 4 | 【用户已定】依据：实测大小，且都不使用 `eval` / `new Function`。放弃：ajv、filtrex、expr-eval（会用 `new Function`）、@bufbuild/cel（体积大、还是 Beta） |
| 8 | 首次安装默认订阅官方「翻译」和「常见大模型」两个规则包 | 【用户已定】放弃：让用户手动订阅 |
| 9 | 视觉用「猫毛色」配色，界面以原型 v5 为准；正式插画到位前用原型里的占位猫 | 【用户已定】配色和交互；【本规格提议】占位插画。放弃：沿用 ScriptCat 风格；猫薄荷绿配色 |
| 10 | Key 用脚本自带的存储明文保存（在脚本猫的「存储」面板里可见），不加主密码 | 【本规格提议】依据：主密码要求每次打开浏览器先解锁，对翻译工具来说代价太大。放弃：主密码加密 |
| 11 | 端到端验证：用 sctl 把构建产物装进真实的脚本猫来测 | 【用户已定】放弃：只用 Playwright 加载打包好的脚本 |
| 12 | 官方规则包和规则 JSON Schema 放在单独的仓库 `scriptscat/companioncat-rules`；脚本仓库以 git 子模块引用它，构建时把固定版本打进内置快照，运行时从规则仓库的地址更新 | 【用户已定】单独一个仓库。【本规格提议】子模块、内置快照、镜像地址。依据：规则可以独立于脚本发版；首次安装不依赖网络；GitHub raw 在部分网络下不稳定，需要备用地址。放弃：规则和脚本放同一个仓库；只靠远程拉取（首次安装要等网络） |

## 1. 运行环境与外壳

- **R1.1 脚本运行范围**：
  - 前提：脚本已装进脚本猫。
  - 结果：在所有 http/https 页面的顶层窗口运行，不在 iframe 里运行。
  - 声明的权限：GM_xmlhttpRequest、GM_getValue / GM_setValue / GM_deleteValue / GM_listValues、GM_addValueChangeListener、GM_registerMenuCommand、GM_setClipboard，以及 `@connect *`。
  - 【本规格提议】
- **R1.2 样式隔离**：
  - 陪伴猫的界面全部放在一个自带 Shadow DOM 的宿主元素里。
  - 结果：网页的 CSS 不改变陪伴猫的外观，陪伴猫的 CSS 也不改变网页。宿主网页根元素的字号不同（比如 `html { font-size: 10px }`）时，陪伴猫的尺寸不受影响。
  - 弹出层（下拉框、菜单、提示）同样挂在这个 Shadow DOM 里。
- **R1.3 角落的小猫**：
  - 前提：当前网站没有关闭小猫，全局设置也没有隐藏它。
  - 结果：页面右下角显示睡觉的小猫，带呼吸动画；系统开了"减少动态效果"时不动。小猫可以拖动，拖到的位置会记住。
  - 点小猫：打开或关闭气泡。
  - 当前网站有划词结果卡片、或者伸出了猫爪时，小猫睁眼。
- **R1.4 打开设置窗口的入口**：小猫气泡里的「打开设置」，以及脚本猫菜单里的「打开陪伴猫设置」。即使小猫被隐藏，脚本猫菜单也始终可以打开设置窗口。
- **R1.5 设置窗口的布局**：
  - 桌面宽度：居中的窗口，左侧导航分两组：
    - 「功能」：由规则提供的功能页，按规则包优先级排序；
    - 「陪伴猫」：外壳自带的「引擎」「规则」「通用」三页，固定不变。
  - 窄屏（宽度小于 640px）：铺满屏幕，顶部用分段按钮切换分区。
  - 按 Esc 或点关闭按钮关闭。
- **R1.6 没有任何规则时**：
  - 「功能」分组为空，并说明"功能由规则提供"；
  - 引擎页和小猫气泡里，都写着"陪伴猫还什么都不会"，并有一个「订阅官方规则」按钮。
- **R1.7 外观**：浅色、深色、跟随系统三种，在「通用」页设置，默认跟随系统。配色、字体、圆角、描边以原型 v5 的 `styles.css` 为准。
- **R1.8 多个标签页同步**：在一个标签页改了设置、Key 或规则，其他已打开的标签页不刷新就会生效。

## 2. 规则包：订阅、更新、合并

- **R2.1 订阅**：
  - 前提：在「规则」页输入一个 URL，点「订阅」。
  - 结果：拉取并校验规则包。通过后加入订阅列表（排在本地规则之后、其他订阅之前）；新的功能和引擎立即出现。
  - 失败时：拉取失败、内容不是 JSON、或者不符合 Schema，就不加入列表，并提示具体原因（网络错误或 HTTP 状态码；Schema 错误写明字段路径）。
- **R2.2 官方规则包和首次安装**：
  - 【用户已定】官方「翻译」和「常见大模型」两个规则包，以及规则 JSON Schema，放在单独的仓库 `git@github.com:scriptscat/companioncat-rules.git`（【已验证】仓库已存在，目前是空的）。
  - 【本规格提议】规则仓库的目录：
    - `packs/official-translate.json`
    - `packs/official-llm.json`
    - `schema/v1.json`
    - 一个检查脚本：所有 `packs/` 都必须通过 `schema/v1.json` 的校验，并且所有表达式语法正确。
  - 【本规格提议】订阅地址按默认分支 `main` 拼出，每个包有一个主地址和一个镜像地址，按顺序尝试，前一个失败才用下一个：
    - 主地址：`https://raw.githubusercontent.com/scriptscat/companioncat-rules/main/packs/<包>.json`
    - 镜像：`https://cdn.jsdelivr.net/gh/scriptscat/companioncat-rules@main/packs/<包>.json`
    - `$schema` 地址：`https://raw.githubusercontent.com/scriptscat/companioncat-rules/main/schema/v1.json`
  - 【本规格提议】脚本仓库用 git 子模块在 `rules/` 引用规则仓库的某个固定提交。构建时，把这个提交里的两个官方包打进脚本，作为内置快照。
  - 首次运行时：立即用内置快照订阅两个官方包，不用等网络，划词马上能用；之后按 R2.3 从上面的地址更新。
  - 脚本升级时，内置快照的版本比本地缓存新，就用快照替换缓存。
  - `schema` 字段的大版本必须是 1。
- **R2.3 自动更新**：
  - 前提：自动更新开着（默认开）。
  - 动作：打开任意网页时，如果某个规则包距上次检查超过 24 小时，就在后台拉取，带上 ETag 或 If-Modified-Since；有镜像地址时，主地址失败才用镜像。
  - 结果：拿到新内容并校验通过，就替换缓存；多个标签页同时打开时，同一个包在一个检查周期里只拉取一次。
  - 失败时：继续用上一个可用版本，该包标记"最近一次更新失败（原因），先继续用某时间的版本"。
- **R2.4 手动管理**：每个订阅都可以：检查更新、调高或调低优先级、复制订阅地址、取消订阅。取消订阅后，它提供的功能、引擎、视图、契约立即消失；Key 和设置值保留，重新订阅后恢复。
- **R2.5 合并规则**：
  - 本地规则优先级最高，其他订阅按列表顺序。
  - 同一个完整 id（`包id/条目id`）的条目，以优先级高的为准，不做字段级合并。
  - `extends` 可以跨包继承：对象逐层合并，数组整个替换，`null` 表示删除这个字段；继承最多 5 层。
  - `overrides` 只在本地规则里有效，以同样的方式合并到目标条目上。
  - 官方包声明的契约 id 不能被其他包覆盖。
- **R2.6 局部失败**：
  - 情况：某个引擎、入口或视图出现继承的对象找不到、继承成环、缺少必填字段、表达式语法错误。
  - 结果：只停用这一个条目，界面上写明原因（例如"继承的 community/kimi-base 找不到"），同一规则包里的其他条目照常工作。
- **R2.7 规则包的贡献摘要**：「规则」页每个订阅显示它提供了多少功能（含几个入口）、引擎、设置项、气泡开关、视图模板、契约。点进去是详情页，逐项列出这些内容，并附上规则原文。

## 3. 本地规则与 Schema

- **R3.1 规则 JSON Schema**：发布一份机器可读的 Schema（JSON Schema 2020-12），覆盖规则包的全部顶层字段，以及第一期支持的所有设置类型、触发器、步骤、展示位置、组件、动作。两个官方规则包都能通过它的校验。规则文件里写上 `"$schema"` 后，常见编辑器可以据此补全和报错。
- **R3.2 本地规则编辑器**：
  - 在「规则 → 编辑本地规则」里编辑 JSON。
  - 点「检查并保存」时，先做 JSON 解析和 Schema 校验，再检查所有 `{{ }}` 表达式的语法。
  - 结果：没有错误就保存并立即生效。有错误时逐条列出，每条写明行号、字段路径、原因；表达式错误还要附上表达式原文和出错位置。
  - 只要 JSON 能解析并且通过 Schema，即使有表达式错误或继承错误，也允许保存：出错的条目按 R2.6 停用，其他照常生效。
  - 「整理格式」按钮：格式化 JSON，不改变内容。
- **R3.3 本地规则里不能写 Key**：`secret` 只能作为表达式里的变量引用。如果本地规则里出现明显像 Key 的字面量（比如以 `sk-` 开头的长字符串），保存时提示"API Key 请在引擎页面填写"，但不阻止保存。

## 4. 契约

- **R4.1 内置契约**：官方「常见大模型」包声明三个契约，它们的输入、输出都有 JSON Schema：
  - `translate`：输入 `texts[]`、`from`（可选，默认 auto）、`to`、`context`（可选）；输出 `texts[]`，条数和输入相同。
  - `chat`：输入 `messages[]`；输出 `text`。
  - `choose`：输入 `state`、`question`、`options`（选项 id 到说明的映射）；输出 `choice`（必须是某个选项 id）和 `confidence`（0 到 1）。
- **R4.2 规则声明的新契约**：规则包可以在 `contracts` 里声明新契约，字段有：`id`（带 `@大版本号`）、`description`、`input`、`output`、`bridgeable`、`sample`、`view`。声明之后，引擎可以实现它，试运行可以调用它；结果按 `view` 渲染，没写 `view` 就自动生成视图。第一期没有让普通用户直接调用新契约的入口。
- **R4.3 校验**：
  - 每次调用前，用契约的 input Schema 校验输入；不通过就直接失败，错误类型是"输入格式不对"。
  - 每次调用后，用 output Schema 校验输出；不通过时错误类型是"返回格式不对"，并附上原始响应的前 500 个字符，供试运行查看。

## 5. 引擎

- **R5.1 引擎声明**：一个引擎由以下几部分组成：
  - `secrets`：名称、标题、占位符、申请地址、申请地址的显示名；
  - `options`：可调参数，每个有类型、标题、默认值，可选的枚举值；
  - `hosts`：会访问哪些域名，可以用表达式，比如 `{{ host(options.baseUrl) }}`；
  - `limits`：超时、重试（在哪些错误类型上重试、最多几次）、并发数、每分钟最多次数；
  - `implements`：实现了哪些契约；
  - 继承相关：`extends`、`abstract`。`abstract` 为 true 的引擎不出现在引擎列表里。
- **R5.2 `http` 实现**：
  - 能力：
    - 前置步骤 `steps`：结果可以按 `cache` 时长缓存；
    - 请求：method、url、headers，请求体可以是 json / form / text；
    - 响应格式：json、text、sse 流；
    - `output` 映射、`errors` 错误识别；
    - `batch`：按 maxItems / maxChars 拆分，或者 join 合并后再按行拆开；
    - `langMap`：语言代码映射。
  - 请求一律通过 GM_xmlhttpRequest 发出。目标域名不在解析后的 `hosts` 列表里时，拒绝发送，错误类型是"域名未声明"。
- **R5.3 `via` 实现**：
  - 把输入映射成另一个契约的输入，调用它，再用 `output` 映射回本契约，并用 `check` 表达式检查结果。
  - `check` 为 false 时，带着失败原因重试一次；还是不通过，就以"返回格式不对"失败。
  - 官方提供 `llm-translate` 和 `llm-choose` 两个桥接。
- **R5.4 `builtin` 实现**：第一期只定义接口，不提供任何代码适配器。规则里写了 `builtin`、但运行时没有对应适配器时，这个实现被停用，原因写明"这个版本的陪伴猫不支持这个内置适配器"。
- **R5.5 引擎列表**：
  - 「引擎」页左边是列表，按三组显示：可以用 / 填上 API Key 就能用 / 有问题。每项有名称、一行说明、状态点。
  - 右边是选中引擎的详情：
    - 能做什么：列出实现了的契约，标出哪些是"由大模型完成"；
    - API Key：见第 7 节；
    - 模型与参数：根据 `options` 自动生成，改动会写成本地 `overrides`，可以「恢复官方设置」；
    - 启用开关；
    - 试运行：见第 12 节；
    - 规则详情：引擎 id、继承自谁、请求地址。
  - 窄屏：先显示列表，点进去看详情，可以返回。
- **R5.6 共用 Key**：引擎没有自己声明 `secrets`、而是继承来的时候，使用父引擎已经保存的 Key。详情页显示"直接用『父引擎』的 Key"，并给出跳到父引擎的链接。
- **R5.7 每种能力先用谁**：「通用」页里，`translate`、`chat`、`choose` 各选一个先用的引擎。选中的引擎没有 Key 时，提示"还没填 Key，现在先用某某"，并按 `first` 策略自动用下一个可用的引擎。功能里没有指定引擎时，就用这里的选择。

## 6. 调用管道、策略与缓存

- **R6.1 管道顺序**：每次调用都依次经过：
  校验输入 → 域名确认 → 读缓存 → 选择实现 → 限速 → 执行（超时、重试）→ 校验输出 → 统一置信度 → 写缓存 → 记录用量。
- **R6.2 四种策略**：
  - `first`：按指定顺序（没指定就按「每种能力先用谁」）调用，失败就换下一个；全部失败时，返回最后一个错误，并附上每个引擎各自的错误。
  - `race`：并行请求，用第一个成功的结果，取消其余请求。
  - `all`：并行请求，每个引擎各自返回结果或错误；开了流式时，增量结果随时推给调用方。
  - `vote`：并行请求，按输出相同的比例算出置信度；`choose` 比较 `choice`，其他契约比较规范化后的输出。
- **R6.3 错误类型**：所有失败都归入以下几类，每类有固定的提示文字和是否重试：
  - 网络
  - 超时
  - 认证（401/403）
  - 太频繁（429）
  - 服务端（5xx）
  - 输入格式不对
  - 返回格式不对
  - 域名未声明
  - 域名未确认
  - 缺 Key
  - 已停用

  规则在 `errors` 里可以覆盖提示文字，但不能新增类型。
- **R6.4 缓存**：
  - 范围：只缓存 `translate` 的成功结果。
  - 缓存键：引擎 id + 生效参数的摘要 + 输入。
  - 容量：最多 5000 条，满了先删最久没用到的。
  - 命中缓存的结果标记 `cached: true`；「通用」页显示条数和大约占用的空间，可以一键清空。
- **R6.5 用量记录**：每次调用记下引擎、契约、耗时、是否命中缓存、token 数（服务商返回了才记）。第一期只用于试运行和调试，不在界面上做统计。

## 7. API Key 与域名确认

- **R7.1 填写 Key**：
  - 前提：引擎声明了 `secrets`，但还没有填。
  - 界面：显示两步引导："打开某某平台创建 API Key"（链接来自 `helpUrl`）、"复制后粘贴到下面，点『测试并保存』"。下面是 Key 输入框，可以切换明文或隐藏。
  - 下方说明："Key 只存在这台电脑上，只会发给某某域名"。
- **R7.2 测试并保存**：
  - 动作：点「测试并保存」。
  - 结果：用这个 Key 对引擎实现的第一个契约调用一次 `sample`。
    - 成功：保存 Key，启用这个引擎，并显示"测试通过，用时 X 秒：样例的输入和输出"。
    - 失败：不保存，显示错误类型和服务商返回的提示（例如"服务商返回 401，这个 Key 无效或已过期"），并提供「不测试，直接保存」。
- **R7.3 Key 的存储**：
  - 按"定义 secrets 的引擎 + 字段名"保存在脚本存储里。
  - 不出现在日志、试运行显示（打码成前 3 位 + `••••••••` + 后 4 位）、导出的数据和错误信息里。
  - 「删除 Key」会删掉这个 Key，并停用依赖它的引擎。
- **R7.4 域名绑定**：
  - Key 第一次通过测试保存时，记下当时 `hosts` 解析出来的域名，作为"已确认域名"。
  - 之后每次请求，如果要携带 Key、而目标域名不在已确认名单里，就暂停这次请求，在当前页面弹出确认框。框里写明：哪个引擎、哪个规则包从哪个版本更新到哪个版本、以前的域名和现在的域名。两个按钮：
    - 「先停用这个引擎」（主按钮）：停用这个引擎，这次请求失败，错误类型是"域名未确认"。以后可以在引擎详情里重新确认。
    - 「我认识这个地址，允许」：把新域名加入已确认名单，继续这次请求。
- **R7.5 被拦截的请求不会发出**：等待确认、或者用户拒绝期间，这个请求不会以任何形式发到新域名。

## 8. 表达式

- **R8.1 语言**：`{{ }}` 里的内容按 CEL 求值。
  - 白名单函数：concat、replace、split、join、contains、urlencode、base64、hex、md5、sha256、hmacSha256、now、unix、uuid、random、json、extractJson、match、langName、languages、lang、host、has、size，以及 CEL 标准的宏和运算符。
  - `match(text, regex)` 返回第一个匹配的捕获组列表（没有匹配时返回空列表），用于从网页响应里取 token；正则长度不超过 200 个字符，输入文本不超过 1 MB。
  - 不提供任何能访问 DOM、网络或存储的函数。
- **R8.2 模板规则**：
  - 字符串**整段**就是一个 `{{ }}` 时，返回原始值（数组、对象、数字、布尔值）；里面夹着其他文字时，结果转成字符串后拼接。
  - CEL 的整数结果在离开表达式时统一转成 JS 数字；超出安全整数范围时报错。
- **R8.3 可用变量**：`settings`、`vars`、`input`、`secret`、`options`、`selection`、`page`、`site`、`steps`、`response`、`stream`、`result`、`item`、`params`、`value`。在不能用某个变量的位置用了它（比如功能的 `run` 里用 `secret`），按语法错误处理。
- **R8.4 限制**：
  - 每个表达式：语法树最多 2000 个节点、嵌套最深 32 层、列表和 map 最多 1000 项；
  - 单次求值最多 50 ms，超时就失败，并在试运行里显示。
  - 【本规格提议具体数值】

## 9. 功能运行时

- **R9.1 功能与入口**：规则里每个 `feature` 在设置窗口「功能」分组里生成一个菜单页（名称、图标来自规则），页面包括：
  - 顶部：功能说明和总开关；
  - 「共用」：功能级 `settings`；
  - 每个入口一组：入口开关、"它会做什么"、入口自己的 `settings`。
  
  功能和入口默认都是开的。
- **R9.2 「它会做什么」**：根据入口的 `match`、`triggers`、`run`、`present` 自动生成大白话，例如：
  - "在所有网站上留意你选中的文字"
  - "把选中的文字发给你勾选的引擎"
  - "在选中文字旁边显示结果卡片"
  
  每句下面附上对应的规则字段。
- **R9.3 设置类型**：第一期支持 boolean、enum、language、engine、engines、string、number。
  - `scope: "site"` 的设置按网站（hostname）分别保存；
  - `engines` 只能选实现了指定契约、并且没被停用的引擎；还没填 Key 的引擎显示出来，但不能勾选；
  - 设置值按"规则包 + 功能 + 入口 + 设置项"区分保存。
- **R9.4 规则更新后设置怎么处理**：规则包更新后：
  - 已有的设置值保留；
  - 新增的设置项用默认值；
  - 被删掉的设置项清除；
  - 类型变了，或者旧值不再合法（比如枚举里没有这个选项了），就恢复默认值。
- **R9.5 气泡里的快捷项**：
  - 标了 `quick` 的设置出现在小猫气泡里：开关显示为开关；enum、language、engine 显示为紧凑的下拉框；`engines` 标了 `quick: "first"` 时，只显示"主要用"第一个。
  - 气泡里顶部显示当前网站的 hostname。
  - 还有引擎没填 Key 时，显示"还有 N 个引擎没填 Key"，点「去填」打开第一个这样的引擎。
- **R9.6 触发器 `selection`**：
  - 前提：入口启用，`match` 命中当前网址，`enabled` 表达式为 true。
  - 触发条件：选中了文字，文字去掉首尾空白后长度在 `minLength`（默认 1）和 `maxLength`（默认 5000）之间，并且选区不在 `ignoreIn` 列出的元素里（默认是 input、textarea、可编辑区域）。
  - `confirm` 的三种取值：
    - `paw`：在选区末尾伸出猫爪，点了才继续；选区消失或者重新选中时，猫爪消失。
    - `none`：直接继续。
    - `alt`：只有选中时按着 Alt 才继续。
  - 选区落在陪伴猫自己的界面里时不触发。
- **R9.7 触发上下文**：
  - `selection.text`：选中的文字，已去掉首尾空白。
  - `selection.lang`：粗略识别的语种，取值 zh-CN / ja / ko / en / auto，按中日韩文字和拉丁字母的比例判断。
  - `selection.sentence`：选区所在的整句，最多 500 个字符。
  - `selection.rect`：选区的位置。
  - `page.url`、`page.title`。
- **R9.8 步骤**：
  - `set`：把表达式的值写进 `vars`。
  - `call`：调用契约，可以指定策略、引擎列表、输入、`stream`、`as`。
  - 某一步出错时，后面的步骤不再执行；错误交给展示层显示。
- **R9.9 展示位置 `near-selection`**：
  - 卡片出现在选区下方（下方空间不够就放到上方），左右不超出可视区域；窄屏时卡片几乎占满宽度。
  - 卡片在"开始执行"时就出现，不用等结果。
  - `pinnable` 为 true 时可以固定。
  - `closeOn`：按 Esc、点卡片外面、重新选中文字时关闭；固定的卡片不会被自动关闭，只能手动关。
- **R9.10 视图与组件**：
  - 组件：card（header / body）、row、text（可以设置 tone 和 style，包括 reading、reading-lg）、icon、icon-button、button、select、spacer、dots、`result-list`。
  - 视图模板：`views` 加 `use` / `with`，模板里用 `params` 取参数。
  - 没写视图时，按输出格式自动生成：字符串显示为文本，对象显示为键值表，数组显示为列表。
- **R9.11 `result-list`**：
  - 按引擎顺序显示每一项，第一项是主结果（字号更大）。
  - 每一项有四种状态，都可以用规则的 `item` 视图分别定义：
    - 加载中
    - 成功：可以显示 `meta`，比如引擎名、"刚才翻译过，直接用了缓存"
    - 失败：显示错误提示和「重试」
    - 缺 Key：显示「填 Key」
  - 流式结果到达时，逐字更新。
- **R9.12 动作**：
  - `copy`：复制到剪贴板，并给出提示。
  - `retry`：只重试指定的引擎。
  - `rerun`：带着新的 `vars` 重新执行入口，只对这一张卡片有效，不改设置。
  - `open`：打开设置窗口的某个位置，可以是 `feature-settings`，或 `engine:引擎id`。
  - `surface`：`pin` 固定、`close` 关闭。

## 10. 「翻译」功能·划词入口（用户看到的行为）

由官方「翻译」规则包提供，定义见 [产品方向第 7 节](../product-direction.md)。以下是验收时看到的行为：

- **R10.1 第一次划词**：
  - 前提：刚装好脚本，默认订阅了官方规则，还没填任何 Key。
  - 动作：在英文网页上选中一段文字。
  - 结果：
    1. 选区末尾出现猫爪，角落的小猫睁眼；
    2. 点猫爪后，选区下方出现结果卡片。表头显示"英语 → 简体中文"、固定按钮、关闭按钮；
    3. 卡片里依次是：Google 翻译（主结果）、微软翻译两条结果；没填 Key 的大模型不会被默认勾选，不出现在卡片里。
- **R10.2 填了 DeepSeek Key 之后**：
  - 前提：已经给 DeepSeek 填了 Key，并在入口设置里把它勾选为第一个。
  - 结果：卡片里 DeepSeek 是主结果，用阅读字体的大字显示；其他引擎的结果显示在下面。
- **R10.3 中英互译**：
  - 前提：中英互译开着，目标语言是简体中文。
  - 动作：选中一段中文。
  - 结果：翻译成英文。
  
  中英互译关着时，选中中文就按原设置翻译成简体中文。
- **R10.4 卡片里临时换语言**：在卡片表头选另一种语言，所有引擎重新翻译成这种语言；入口和功能的设置都不变。
- **R10.5 各个引擎状态互不影响**：
  - 某个引擎超时或报错，只有它那一项显示错误和「重试」，其他项正常；
  - 勾选了、但 Key 被删掉的引擎，显示「填 Key」，点了打开它的详情；
  - 第二次翻译同一段文字（同样的引擎和设置），命中缓存，并显示"刚才翻译过，直接用了缓存"。
- **R10.6 关闭划词**：
  - 在气泡里关掉「在这个网站划词翻译」后，这个网站上选中文字不再伸出猫爪，其他网站不受影响。
  - 在功能页关掉「划词翻译」入口或「翻译」功能后，所有网站都不再触发。
- **R10.7 输入框和编辑区**：在 input、textarea、可编辑区域里选中文字，不伸出猫爪。
- **R10.8 网页对照入口**：本期不实现。规则里如果出现 `entries.page`，它在功能页里显示为一组，注明"这个版本的陪伴猫还不支持这个入口"，开关不能打开；划词入口不受影响。

## 11. 官方规则包

- **R11.1 「翻译」（`official-translate`）**：
  - 引擎：Google 翻译（免费接口）、微软翻译（必应网页翻译接口：先取 bing.com/translator 页面里的 token，再调用翻译；原 edge.microsoft.com/translate/auth 已于 2026-11 失效），都只实现 `translate`，都写成 `http` 实现；
  - 视图模板：`translation-card`；
  - 功能：`translate`，含共用设置（翻译成、中英互译）、`selection` 入口、`page` 入口（本期不运行，见 R10.8）。
- **R11.2 「常见大模型」（`official-llm`）**：
  - 契约：`translate`、`chat`、`choose`；
  - 桥接：`llm-translate`、`llm-choose`；
  - 抽象引擎 `openai-compatible`：支持 Chat Completions 和 Responses 两种接口，按 `options.api` 选用；chat 实现走 SSE 流式；
  - 具体引擎：DeepSeek、智谱 GLM、通义千问、OpenAI 继承它；
  - Jev：`http` 实现 `choose`。
- **R11.3 两个包都能通过 R3.1 的 Schema 校验**，并且作为文档里的范例，覆盖以下写法：签名或取 token 的多步请求、流式响应、`via` 桥接、`extends`、`options`、视图模板。

## 12. 试运行

- **R12.1 运行**：
  - 前提：引擎可以用。
  - 动作：在引擎详情点「用样例试运行」，选择一个它实现了的契约。
  - 结果：用这个契约的 `sample` 调用一次（不读也不写缓存），按步骤展示：
    - 桥接到了哪个契约；
    - 每一步请求的方法、地址、请求头、请求体（Key 按 R7.3 打码）；
    - 响应的状态码、耗时、流式片段数；
    - 每个表达式的原文和算出的值；
    - 最终输出，或者错误类型和原因。
- **R12.2 出错时**：显示在第几步、哪个表达式出错。原始响应超过 2000 个字符时截断，可以展开看完整内容。

## 13. 兼容性、隐私、无障碍

- **R13.1 浏览器**：支持当前版本的 Chrome、Edge、Firefox 上的脚本猫。网页开了严格 CSP（禁止 `unsafe-eval`）时，所有功能照常工作。
- **R13.2 隐私**：
  - 不收集任何使用数据；
  - 除了用户触发的翻译请求、规则包拉取、Key 测试，以及引擎规则 `steps` 里的前置请求，不发出任何其他网络请求；
  - 划词时只发送选中的文字、所在的整句和目标语言。
- **R13.3 无障碍**：
  - 所有交互元素都能用键盘操作，焦点有可见的描边；
  - 图标按钮有名称（`aria-label`）；
  - 弹窗打开时，焦点留在弹窗里，关闭后回到触发它的元素；
  - 对比度达到 WCAG AA；
  - 系统开了"减少动态效果"时关闭动画。
- **R13.4 界面状态**：界面以原型 v5 为准，必须覆盖原型里的这些状态：
  - 没有规则；
  - 首次打开（欢迎）；
  - 填 Key、Key 测试失败、共用 Key；
  - 引擎有问题；
  - 规则更新失败；
  - 本地规则校验出错；
  - 划词的猫爪、卡片（加载中、成功、失败、缺 Key、缓存）；
  - 域名变更确认；
  - 深色；
  - 窄屏。

## Out of scope

- 「翻译」的网页对照入口，以及它需要的 `command`、`page-load` 触发器、`select`、`inline-after` 等：第四期。
- 网站自动化（点击、填写等动作）、Jev 在功能里的实际使用、置信度门槛和"先问你"的交互、用 AI 写规则：第二期。规则格式里给 `sites` 留了位置，但第一期只用它调整功能参数。
- 做题：第三期。
- 普通用户直接调用任意契约的通用入口、沙箱应用（兼容 MCP Apps）、MCP 服务器引擎、对外给其他脚本调用的接口：以后再排期。
- `builtin` 代码适配器的具体实现、iframe 内运行、预算上限、用量统计界面、规则市场。
- 发布渠道（脚本猫脚本站上架、自动更新地址）。
