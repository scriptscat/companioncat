# 陪伴猫

陪伴猫（CompanionCat）是一个运行在[脚本猫（ScriptCat）](https://scriptcat.org)里的用户脚本。网页角落趴着一只睡觉的小猫，平时不打扰你；需要的时候，它用规则里定义好的引擎帮你翻译、跳过广告、做题，或者照你教它的方式操作网页。

陪伴猫本身只是一个外壳：功能、设置项、引擎都来自订阅的规则包。规则只是 JSON 加受限的 CEL 表达式，不执行任何代码。

## 功能

装上后默认订阅全部官方规则包，下面这些功能直接可用：

| 功能 | 怎么用 |
|---|---|
| 划词翻译 | 选中文字，先伸出一只猫爪，点一下就翻译。卡片里同时显示几个引擎的译文，可以临时换目标语言、复制、固定 |
| 网页对照 | 按 Alt+A、点小猫气泡里的「对照翻译这个网页」或用脚本猫菜单。译文插在每段后面，滚到哪里翻到哪里；可以「只看译文」；再按一次恢复原样。也可以设成打开某个网站时自动对照 |
| 跳过广告 | 在某个网站打开后，页面上新冒出「跳过」「关闭广告」按钮时，小猫把候选按钮交给引擎判断：有把握（默认 85%）就点，没把握先问你 |
| 做题 | 在练习页点气泡里的「帮我做这页的题」。识别单选、多选、填空，有把握（默认 80%）的直接勾选或填入，没把握的标出建议答案；最后列出结果卡片。**不会点提交**，检查后自己交卷 |
| 教小猫做件事 | 像聊天一样告诉小猫想让它在网页上做什么，可以在页面上点选相关的元素。小猫用你自己的对话引擎写出规则草稿，每一版都自动校验、在当前页面试运行（不动手）；满意后存进本地规则，之后还能接着和它改 |

引擎：

| 引擎 | 说明 |
|---|---|
| Google 翻译、微软翻译 | 免费，不用填 Key，划词和网页对照默认用它们 |
| DeepSeek、智谱 GLM、通义千问、OpenAI | 填 API Key 后可用于翻译、对话和选择；都基于「OpenAI 兼容」，支持 Chat Completions 和 Responses 两种接口 |
| Jev | 回答选择题并自带置信度，适合跳过广告和做题。目前在早期体验阶段，需要申请 |

跳过广告、做题要一个能做「选择」的引擎（Jev 或任一大模型），做题的填空和教小猫做件事要一个「对话」引擎（任一大模型），都要先在设置窗口的「引擎」页填好 Key。

其他兼容 OpenAI 接口的服务，可以在本地规则里继承「OpenAI 兼容」加一个引擎，见[规则作者指南](https://github.com/scriptscat/companioncat-rules#readme)。

## 安装

先在浏览器里装好脚本猫扩展，然后任选一种：

- **GitHub Releases**：打开 <https://github.com/scriptscat/companioncat/releases/latest/download/companioncat.user.js>，脚本猫会弹出安装页。从这里装的版本会自动跟着新的 Release 更新。
- **脚本猫脚本站**：在 [scriptcat.org](https://scriptcat.org) 搜索「陪伴猫」安装。

装好后打开任意网页，角落里就有小猫。点它打开气泡；气泡里的「打开设置」打开设置窗口。

## 隐私与控制

- **Key 只留在本机。** API Key 明文存在脚本自己的存储里（脚本猫的「存储」面板能看到），不写进规则；试运行里的 Key 打码，动作记录里没有 Key。
- **Key 只发往确认过的域名。** 每个引擎都声明了会访问哪些域名，不在列表里的请求一律拒绝。规则更新后请求的域名变了，要你确认才会继续发 Key。
- **发出去的内容会写明。** 划词和网页对照只把要翻译的文字发给所选的翻译引擎。跳过广告和做题会把按钮或题目附近的精简结构发给判断用的引擎（不含输入框里的值）；打开前会写明发送什么、发到哪个域名。教小猫做件事会把对话、你点选的元素的精简结构、当前网址和标题发给你的对话引擎，第一次使用时会提示。
- **自动化默认关闭，打开要你同意。** 订阅来的规则里，会点击、填写或把页面内容发出去的入口默认关闭。第一次打开时，确认框写明它会做哪些动作、发送什么内容到哪里、在哪些网站生效、来自哪个规则包。规则更新后动作种类或发送地址变了，会自动暂停，再问你一次。你自己写的或教小猫写的本地规则，保存后直接生效。
- **随时能看、随时能停。** 有自动化生效的网站上，小猫气泡里可以一键「在这个网站暂停自动化」，并列出这个网站最近 20 条动作记录。
- **陪伴猫不限制规则能做什么。** 点不点提交、填不填密码框由规则自己决定（官方「做题」规则就不点提交）。只订阅你信任的规则包。

## 规则

功能和引擎都写在规则包里。官方规则包、规则的 JSON Schema 和检查脚本在单独的仓库 [scriptscat/companioncat-rules](https://github.com/scriptscat/companioncat-rules)，本仓库以 git 子模块的形式放在 `rules/`，构建时把官方包打进脚本作为内置快照，首次安装不用等网络；之后陪伴猫每天从规则仓库检查一次更新。

- 订阅别的规则包：设置窗口的「规则」页，输入地址点「订阅」。
- 写自己的规则、修改订阅里的引擎或功能：「规则」页的「编辑本地规则」。
- 怎么写规则：[规则作者指南](https://github.com/scriptscat/companioncat-rules#readme)。

## 开发

需要 Node.js 和 pnpm 9（`packageManager` 里写了版本，可以用 corepack）。

```sh
git clone --recursive https://github.com/scriptscat/companioncat.git
cd companioncat
pnpm install
```

已经克隆过的，用 `git submodule update --init` 拉取 `rules/`。

| 命令 | 作用 |
|---|---|
| `pnpm test` | 单元测试和界面组件测试（Vitest） |
| `pnpm typecheck` | TypeScript 类型检查 |
| `pnpm build` | 构建到 `dist/companioncat.user.js` 和 `dist/companioncat.meta.js`，并检查构建产物 |

端到端测试用 `sctl` 命令行驱动你自己浏览器里的脚本猫，在本地测试页上跑一遍（需要先让 sctl 连上脚本猫）：

```sh
pnpm build
node e2e/install.mjs   # 第一次：把构建产物装进脚本猫，在浏览器里点同意
pnpm e2e               # 全部场景；--list 列出场景
```

改了官方规则包时，在 `rules/` 里跑 `node scripts/check.mjs` 检查。

## 发布

```sh
pnpm release patch          # 或 minor、具体版本号，例如 1.0.0
pnpm release minor --dry-run   # 只看会做什么，不改文件、不提交
```

要求在 `main` 上、工作区干净、和 `origin/main` 同步，并且装好已登录的 `gh`。它会依次：跑测试、类型检查和构建，更新 `package.json` 的版本号和 `CHANGELOG.md`，提交并打 `v<版本>` 标签，推送，再创建 GitHub Release，附上 `companioncat.user.js` 和 `companioncat.meta.js`。从 Releases 安装的用户会据此自动更新。脚本猫脚本站上的版本另外发布。

规则包单独发布：推到规则仓库的 `main` 后，用户在一天内收到更新；新版脚本构建时会带上 `rules/` 子模块指向的那一版作为内置快照。
